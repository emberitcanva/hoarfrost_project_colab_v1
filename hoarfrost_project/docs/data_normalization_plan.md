# План нормализации исходных временных рядов для моделей Макконена и Горячева

## Назначение документа

Этот документ фиксирует согласованный подход к предварительной обработке исходных временных рядов перед расчётами по моделям Макконена и Горячева. Цель — обеспечить воспроизводимость, преемственность и прозрачность обработки данных без численной подгонки и без выдумывания отсутствующих значений.[cite:280][cite:284][cite:288]

В качестве исходных данных рассматриваются три файла:
- `Sensor-VL-module-3-No0039-wide-ffill.csv` — сенсорный ряд линии;
- `Meteostation-2304-MSR0011-wide-ffill.csv` — ряд метеостанции;
- `METAR-Yakutsk.csv` — внешний ряд по фактической облачности с иной структурой, используемый как дополнительный источник для переменных облачности и, при необходимости, для контроля качества времени наблюдений.[cite:280]

## Что анализируется

Нормализация должна проводиться не на уже рассчитанных величинах, а на самих исходных наблюдениях: временных метках, пропусках, кратности измерений, регулярности шага и согласованности рядов между собой.[cite:285]

Анализу подлежат:
- структура временных меток `created_at`;
- фактическое распределение интервалов между наблюдениями;
- наличие дубликатов и неупорядоченных записей;
- пропуски по длине и по сезону;
- покрытие данных по месяцам и по зимним эпизодам;
- пригодность отдельных переменных для локальной интерполяции или только для внешнего восстановления.[cite:284][cite:288]

## Базовые принципы

Перед любым gap-filling временной ряд должен быть приведён к регулярной сетке, а сами timestamps — проверены и при необходимости восстановлены как задача regular interval time series repair, а не как побочный шаг интерполяции значений.[cite:285]

Общепринятая практика для метеорологических и экологических рядов состоит в следующем: короткие пропуски можно восполнять локальными методами, средние — только ограниченно и с оглядкой на физику переменной, длинные — либо восстанавливать внешними эталонными источниками, либо оставлять как missing с разрывом расчётного эпизода.[cite:280][cite:282][cite:284][cite:288]

## Целевой формат обработки

### Этап 1. Аудит времени

Для каждого файла отдельно выполняется:
- сортировка по времени;
- проверка дубликатов timestamp;
- проверка обратных скачков времени;
- расчёт `delta_t` между соседними наблюдениями;
- оценка базового шага сетки по моде и медиане интервалов.[cite:285]

Именно на основании этого этапа определяется стандартный временной шаг, на который затем будут пересажены ряды. Значение шага не задаётся заранее вручную, а выбирается по фактической структуре наблюдений.[cite:285]

### Этап 2. Регуляризация временной сетки

После аудита каждый ряд переводится на регулярную сетку времени с использованием выбранного стандартного шага. Для сенсорного и метеорологического ряда сетка должна быть общей, чтобы последующее объединение выполнялось по точному времени, а не по `nearest merge_asof` без ограничений.[cite:285]

Для `METAR-Yakutsk.csv` допускается отдельная сетка на его собственной частоте с последующим аккуратным приведением к общей сетке только для переменной облачности и сопутствующих полей, если они будут использоваться в расчётах.[cite:280]

### Этап 3. Инвентаризация пропусков

После регуляризации для каждого ряда строится таблица gap-сегментов с полями:
- время начала пропуска;
- время окончания пропуска;
- длительность пропуска в секундах, часах и в числе шагов сетки;
- сезон/месяц пропуска;
- затронутые переменные.[cite:284][cite:288]

Эта таблица становится основой политики заполнения и разрыва расчётных эпизодов.

## Категории пропусков

Окончательные пороги должны быть выбраны по реальному распределению `delta_t`, но базовая схема категорий может быть зафиксирована заранее как рабочая рамка:[cite:284][cite:288]

| Категория | Определение | Рекомендуемое действие |
|---|---|---|
| Короткий gap | До 1–3 шагов регулярной сетки | Допустимо локальное заполнение по физически оправданному правилу [cite:284][cite:291] |
| Средний gap | От нескольких шагов до нескольких часов | Ограниченное заполнение только для части метеопеременных; сенсорные динамические величины лучше не дорисовывать [cite:284][cite:288] |
| Длинный gap | Много часов, сутки и более | Не заполнять внутрисерийной интерполяцией; использовать внешний источник или разрывать расчётный эпизод [cite:282][cite:288] |
| Очень длинный gap | Многосуточные и сезонные разрывы | Не восстанавливать по внутреннему ряду; запускать новый независимый эпизод расчёта [cite:282][cite:288] |

## Политика по переменным

### Сенсорный файл `Sensor-VL-module-3-No0039-wide-ffill.csv`

Переменные сенсора относятся к разным физическим классам, и для них не должен применяться единый метод gap-filling.

#### Группа A. Метеоподобные локальные переменные сенсора
- `tvozd`;
- `tcab`;
- `rh`.

Для очень коротких gaps допустима локальная интерполяция при условии, что она не создаёт неестественных скачков по скорости изменения. Для средних и длинных gaps эти переменные лучше не домысливать без внешней опоры.[cite:284][cite:291]

#### Группа B. Электрические и эксплуатационные переменные
- `iideistv` и связанные токовые поля;
- служебные статусные признаки.

Для этих переменных допустим только очень ограниченный подход на коротких gaps; длинные интервалы нельзя заполнять линейно, потому что это уже будет генерация несуществующего режима линии, а не нормализация данных. Для средних и длинных gaps должен фиксироваться разрыв эпизода.[cite:289]

#### Группа C. Угловые измерения
- `ugol1`;
- `ugol2`.

Угловые ряды особенно чувствительны к ложной интерполяции, потому что напрямую входят в механику Горячева. Для коротких gaps можно обсуждать локальную интерполяцию только после анализа характерных скоростей изменения. Для средних и длинных gaps углы следует оставлять missing, а расчёт механики на этих участках не выполнять.[cite:284][cite:289]

### Метеостанция `Meteostation-2304-MSR0011-wide-ffill.csv`

#### Группа D. Плавные метеопеременные
- давление;
- температура;
- влажность;
- ветер (только с осторожностью).

Для коротких gaps допустима линейная интерполяция или nearest/persistence в зависимости от переменной. Для средних gaps предпочтительнее опираться на внешний эталонный ряд, если он доступен. Для длинных gaps внутрисерийное заполнение не рекомендуется.[cite:282][cite:284][cite:291]

#### Группа E. Облачность и радиационно значимые переменные
- фактическая облачность;
- производные величины, влияющие на длинноволновый/солнечный баланс.

Для них предпочтительно использовать внешний фактический ряд `METAR-Yakutsk.csv`, а не рисовать длинные участки интерполяцией внутри станции. Это особенно важно для модели Макконена, где облачность напрямую влияет на радиационный член теплового баланса.[cite:280][cite:282]

### Файл `METAR-Yakutsk.csv`

Этот файл рассматривается как внешний референс для облачности и, при необходимости, для сопутствующего контроля синхронности метеоусловий. Из-за иной структуры он должен сначала пройти отдельный этап парсинга и приведения к общей схеме временных меток, после чего использоваться только для согласованных полей, а не как механическая подмена всего ряда метеостанции.[cite:280]

## Что не нормализуется интерполяцией

Следующие величины не должны заполняться как исходные наблюдения:
- `H(t)`;
- `rho_t(t)`;
- `mass_per_m(t)`;
- `prev_delta_T_c`;
- любые расчётные поля Макконена и Горячева.[cite:143][cite:134]

Это не входные измерения, а производные состояния модели. При длинных разрывах они должны переинициализироваться или пересчитываться заново в новом эпизоде, а не «протягиваться» через пропуск.[cite:288]

## Политика разрыва эпизодов

После выявления средних и длинных gaps должен вводиться механизм `episode split` — расчётный ряд разбивается на независимые эпизоды. Это особенно важно для модели Макконена, потому что переходные величины зависят от шага времени и от предыдущего состояния провода.[cite:143][cite:288]

Для нового эпизода должны заново задаваться начальные условия модели, по крайней мере:
- `prev_delta_T_c = 0`;
- оценка необходимости `H(t0)=0` и `rho_t(t0)=0`, если пропуск слишком длинный и сохранение льда без наблюдений не может быть обосновано.[cite:142][cite:143]

Такой подход не создаёт новые данные, а корректно отражает потерю наблюдаемости системы на длинном интервале.[cite:288]

## Что будет встроено в модель, а что останется отдельным этапом

### Отдельный Colab-документ / ноутбук

Первичный аудит данных и выработка порогов должны быть оформлены как отдельный воспроизводимый Colab-блок или отдельный notebook. Это позволит:
- анализировать структуру пропусков независимо от физической модели;
- пересчитывать статистику gaps при обновлении исходных файлов;
- документировать выбранные пороги и политику заполнения.[cite:285]

### Встроенная часть в рабочую модель

После того как политика будет подтверждена, в основной pipeline можно встроить:
- модуль `time_grid_audit` / `data_normalization`;
- построение регулярной сетки;
- маркировку gaps;
- применение правил заполнения только для допустимых переменных и только на допустимых длинах пропуска;
- разбиение на эпизоды перед `calibration.py` и `makkonen_model.py`.[cite:134][cite:141]

Итоговая логика будет такой:
1. чтение исходных CSV;
2. аудит времени и пропусков;
3. нормализация/регуляризация рядов;
4. формирование эпизодов;
5. калибровка;
6. расчёт Макконена;
7. расчёт Горячева;
8. сравнение толщины.[cite:134][cite:141]

## Практический план следующего шага

Следующим техническим шагом должен стать не пересчёт физики, а именно аудит пропусков по трём исходным файлам:
- распределение `delta_t`;
- список всех gap-сегментов;
- покрытие по месяцам;
- оценка наиболее типичного шага наблюдений;
- предварительная классификация gaps на short / medium / long / very long.[cite:285][cite:284]

Только после этого можно обоснованно принять численные пороги для fill policy и episode split, не прибегая к подгонке модели.[cite:280][cite:288]
