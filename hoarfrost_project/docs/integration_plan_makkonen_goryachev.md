# План построения кода: интеграция моделей Макконена и Горячева

Основание:

- использовать только сохранённые рабочие реестры формул Макконена и Горячева (`makkonen_equations_corrected.md`, `goryachev_formulas_corrected.md`);
- не вводить собственные физические формулы без подтверждения пользователем;
- любые недостающие формулы, параметры, соглашения о знаках и исходные данные запрашивать отдельно;
- численные значения входных параметров для кейса `case_01` брать только из `input_case_01_numeric_registry.md`.

---

## 1. Принцип работы

Интеграция строится из двух независимых расчётных блоков:

1. **Блок Макконена**:
   - рассчитывает образование/убыль изморози;
   - обновляет состояние слоя льда во времени;
   - выдаёт:
     - толщину H(t),
     - плотность формирующегося льда rho(t),
     - среднюю плотность слоя rho_t(t),
     - массу льда на единицу длины.

2. **Блок Горячева**:
   - рассчитывает геометрию и силу тяжения провода;
   - использует температуру, угол наклона, угол кручения, длину пролёта и связанные параметры;
   - при наличии согласованной связи с обледенением использует параметры состояния слоя льда.

3. **Связующий слой**:
   - переводит результаты блока Макконена в те входы блока Горячева, которые реально подтверждены пользователем;
   - если для такого перехода не хватает формулы или соглашения, расчёт не выполняется автоматически и помечается как требующий уточнения.

---

## 2. Жёсткие правила реализации

При написании кода соблюдать:

- использовать только формулы из файлов:
  - `makkonen_equations_corrected.md`
  - `goryachev_formulas_corrected.md`
- не вводить дополнительные физические формулы «из памяти»;
- не подставлять типовые значения параметров без явного разрешения пользователя;
- не домысливать единицы измерения, если они неоднозначны;
- при любой неопределённости создавать вопрос пользователю и помечать зависимую часть кода как TODO / NotImplemented;
- состояние изморози (H(t), rho(t), rho_t(t), масса льда) переносить с шага на шаг; **не обнулять его автоматически**;
- для кейса `case_01` численные входные значения брать только из `input_case_01_numeric_registry.md`.

## 4. Содержимое модулей

### 4.1. `common_types.py`

Содержит только структуры данных:

- `MeteoInput`
- `CablePhysicalParams`
- `GoryachevCalibrationParams`
- `SensorSnapshot`
- `HoarfrostState`
- `MechanicalState`
- `CoupledState`

Без расчётной физики.

### 4.2. `makkonen_model.py`

Должен включать только функции, напрямую соответствующие реестру формул Макконена:

- `eq1_deposition_rate(...)`      → формула (1)
- `eq2_energy_balance_residual(...)` → формула (2)
- `eq3_latent_heat_flux(...)`    → формула (3)
- `eq4_convective_flux(...)`     → формула (4)
- `eq5_heat_transfer_coefficient(...)` → формула (5)
- `eq6_nusselt_free(...)`        → формула (6)
- `eq7_grashof_number(...)`      → формула (7)
- `eq8_nusselt_forced(...)`      → формула (8)
- `eq9_longwave_clear_sky(...)`  → формула (9)
- `eq10_longwave_cloud_correction(...)` → формула (10)
- `eq11_internal_heat_flux(...)` → формула (11)
- `eq12_cable_temperature(...)`  → формула (12)
- `eq13_ice_conductivity(...)`   → формула (13)
- `eq14_thermal_inertia_power(...)` → формула (14)
- `eq15_forming_hoarfrost_density(...)` → формула (15)
- `update_hoarfrost_state(...)`  → дискретное обновление H, rho, rho_t, массы по согласованному алгоритму.

Важно:

- функция `update_hoarfrost_state` может использовать только тот дискретный алгоритм обновления массы/толщины, который был отдельно согласован в диалоге;
- функция **не имеет права** обнулять состояние изморози на каждом шаге;
- при изменении логики обновления функция должна быть переписана в соответствии с обновлёнными решениями и отмечена в `decisions_log`.

### 4.3. `goryachev_model.py`

Должен включать только функции, напрямую соответствующие реестру Горячева:

- `eq1_q0_from_temperature(...)`
- `helper_u_from_phiH(...)`
- `eq2_L0(...)`
- `eq3_L0T(...)`
- `eq4_phiK0(...)`
- `eq5_L0g(...)`
- `eq6_tension(...)`
- `eq7_sag(...)`
- `eq8_sensitivity_phiK(...)`
- `eq9_sensitivity_phiH(...)`
- `eq10_sensitivity_T(...)`
- `eq11_total_error(...)`
- `eq12_ice_wall_thickness(...)`

Для формул (8)–(10) допустима только численная производная, если пользователь это отдельно подтвердит. Иначе оставить как интерфейс-заглушку.

### 4.4. `coupling_layer.py`

Только интерфейс связывания моделей.

Функции вида:

- `hoarfrost_outputs_to_mechanical_inputs(...)`
- `update_coupled_state(...)`

Физическое наполнение должно использовать только явно согласованные мосты между моделями.

На текущий момент подтверждённый мост:

- при сравнении толщины: `q0g = rho_t(t*)` в формуле (12) Горячева.

Все остальные мосты (`Fg`, модификация `q0` и т.п.) должны возвращать статус `"requires_user_formula"` до отдельного решения.

### 4.5. `simulation_runner.py`

Оркестратор шагов времени:

1. считывает входы на шаге `n` (из подготовленного DataFrame, сформированного `calibration.py`);
2. обновляет состояние Макконена;
3. пытается выполнить согласованный coupling;
4. если связь определена — обновляет состояние Горячева;
5. сохраняет все промежуточные переменные и флаги неопределённости.

### 4.6. `validation_checks.py`

Проверки без новой физики:

- значения не NaN;
- толщина `H >= 0`;
- масса льда `>= 0`;
- подкоренные выражения в формулах неотрицательны;
- при отсутствии льда `H = 0`;
- при `t_c >= 0` в модели Макконена обледенение выключается только в соответствии с уравнениями;
- предупреждение, если в формуле (2) Горячева выбрана неверная ветвь знака;
- предупреждение, если углы переданы в градусах/радианах не в соответствии с соглашением.

## 5. Полный реестр доступных исходных данных

Только список, без численных значений.

### 5.1. Метеоданные и внешняя среда (Макконен)

- `t_a` — температура воздуха
- `t_s` — температура поверхности льда
- `t_c` — температура кабеля
- `e_a` — давление водяного пара в воздухе
- `e_s` — давление насыщенного пара над льдом
- `p_a` — атмосферное давление
- `v` — скорость ветра
- `n` — облачность
- `q_S` — коротковолновая солнечная радиация
- `g` — ускорение свободного падения
- `nu` — кинематическая вязкость воздуха
- `sigma` — постоянная Стефана-Больцмана
- `c_p` — теплоёмкость воздуха
- `k_a` — теплопроводность воздуха
- `L_e` — удельная теплота сублимации

### 5.2. Параметры кабеля/льда (Макконен)

- `d` — диаметр кабеля без льда

- `rho_t` — средняя плотность слоя изморози
- `rho_c` — плотность материала кабеля
- `c_c` — удельная теплоёмкость материала кабеля
- `Delta_T_c` — изменение температуры кабеля за шаг
- `Delta_tau` — шаг времени модели
- `I` — скорость образования льда
- `H` — средняя толщина изморози
