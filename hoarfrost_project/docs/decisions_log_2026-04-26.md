# Зафиксированные решения по формулам и исходным данным

Дата фиксации: 2026-04-26 (актуализировано после добавления case_01)

## 1. Правило включения новых формул

В модель можно включать дополнительные формулы, если:

- необходимость формулы выявлена при построении расчёта;
- формула представлена пользователю в явном виде;
- вместе с формулой даны описание переменных и ссылка на источник;
- пользователь отдельно подтвердил её использование.

До выполнения этих условий новая формула не считается рабочей и в код не включается.

## 2. Принятые решения по исходным данным

### 2.1. Параметр alpha*

Решение:

- `alpha*` не запрашивать как независимый обязательный исходный параметр;
- задавать его через подтверждённую формулу.

Формула:

- `alpha* = 1 / (A - C^2 / B)`

где:

- `alpha*` — удельное относительное удлинение, 1/Н;
- `A` — жёсткость каната на растяжение, Н;
- `B` — жёсткость каната на кручение, Н·м²;
- `C` — коэффициент жёсткости/связи, Н·м.

### 2.2. Параметр es

Решение:

- исходных данных по `es` нет;
- используется подтверждённая формула для давления насыщенного пара над льдом.

Формула:

- `es = 611.2 * exp(22.46 * ts / (272.62 + ts))`

где:

- `es` — давление насыщенного водяного пара над льдом, Па;
- `ts` — температура поверхности льда, °C.

Источник: WMO Guide to Meteorological Instruments and Methods of Observation (CIMO Guide, 2008), формула для vapor pressure over ice; приведена также в обзоре Holger Vömel / CIRES / NCAR.

### 2.3. Начальная масса льда на единицу площади

Решение:

- начальная масса льда на единицу площади принимается равной 0.

При этом:

- начальные значения толщины и средней плотности слоя задаются в файле `input_case_01_numeric_registry.md` (для case_01) или аналогичном реестре для других кейсов.

### 2.4. Площадь поперечного сечения F

Решение:

- данные по `F` задаются пользователем;
- параметр остаётся внешним входом;
- для case_01 значения `F` берутся из `input_case_01_numeric_registry.md`.

### 2.5. Разность высот точек подвеса

Решение:

- принять равной 0;
- в расчёте не учитывать.

### 2.6. Известная сила тяжения в момент калибровки

Решение:

- данных нет;
- как обязательный вход не использовать.

### 2.7. Погрешности ΔφK, ΔφH, ΔT

Решение:

- блок погрешности не требуется;
- параметры из анкеты обязательных данных исключить;
- в коде не реализовывать расчёт ΔF на основе (8)–(11) Горячева до отдельного решения.

### 2.8. Константы g и sigma

Решение:

- считать константами;
- численные значения задаются в реестрах входных данных (например, `input_case_01_numeric_registry.md`).

## 6. Подтверждённая вычислительная схема для Qt и ts в модели Макконена

Принято:

- на шаге времени `Qt` считается по предыдущему значению `ΔTc`;
- температура поверхности льда `ts` ищется численно внутри текущего шага при фиксированном `Qt`.

Комментарий:

- это вычислительная схема реализации уже подтверждённых уравнений Макконена;
- новая физическая формула при этом не вводится.

## 7. Добавленные рабочие формулы ea и QJ и модуль калибровки

Принято:

- добавить в перечень рабочих формул:
  - формулу вычисления `ea` по температуре воздуха и относительной влажности;
  - формулу вычисления `QJ` по току линии и сопротивлению провода на единицу длины;
- использовать модуль `calibration.py` как предобработку перед модулями Макконена и Горячева.

Формулы:

- `e_sat(ta) = 611.2 * exp(22.46 * ta / (272.62 + ta))`
- `ea = (RH / 100) * e_sat(ta)`
- `QJ = I^2 * R'`

Численное значение сопротивления для текущего объекта:

- `R' = 0.0004218` Ом/м (может быть изменено по отдельному решению).

## 10. Численные улучшения решателя Макконена (solve_surface_temperature)

**Статус:** включено в экспериментальную ветку, допускается отмена или замена.

### 10.1. Кинематическая вязкость воздуха ν(T)

Решение:

- Перейти от постоянного ν к табличной аппроксимации ν(T_a) для сухого воздуха при ~1 атм.
- Использовать табличные значения ν(T) из инженерных справочников (например, Engineering Toolbox, Matmake) для температур в диапазоне от -30 до +30 °C.[web:92][web:99]
- Реализовать функцию:

  - хранить словарь:
    - -30 °C → 1.08e-5 м²/с  
    - -20 °C → 1.16e-5 м²/с  
    - -10 °C → 1.24e-5 м²/с  
    - 0 °C   → 1.33e-5 м²/с  
    - 10 °C  → 1.42e-5 м²/с  
    - 20 °C  → 1.51e-5 м²/с  
    - 30 °C  → 1.60e-5 м²/с [web:99]

  - для произвольной ta_C:
    - ограничивать ta_C в диапазоне [-30; 30];
    - интерполировать ν по температуре линейно (numpy.interp).

- Функция получает вид:

  ```python
  def nu_air_m2_s(ta_C: float) -> float:
      temps = np.array(sorted(NU_TABLE.keys()), dtype=float)
      nus = np.array([NU_TABLE[t] for t in temps], dtype=float)
      t_clamped = float(np.clip(ta_C, temps, temps[-1]))
      return float(np.interp(t_clamped, temps, nus))
  ```

- Вызов solve_surface_temperature перестроить так, чтобы ν не передавалось снаружи как константа, а вычислялось внутри как nu_air_m2_s(ta_C).

Комментарий:

- Это чисто численное улучшение, не меняющее структуру модели Макконена, и может быть отменено заменой на другую ν(T) или на табличные значения из более точного источника (например, НИСТ).[web:94]

### 10.2. Улучшение итерации по уравнению теплового баланса (2)

Решение:

- Текущее упрощение solve_surface_temperature (T_s ← T1_C - 0.01 * residual) заменить на более устойчивое решение уравнения:

  \[
  R(T_s) = q_e(T_s) + q_s + q_i - q_c(T_s) - q_\text{eff}(T_s) = 0
  \]

- Ввести функцию невязки:

  ```python
  def heat_balance_residual(T_s_C, ta_C, e_a_pa, p_a_pa, v_m_s, n_tenths,
                            qS_w_m2, QJ_w_m, prev_delta_T_c_K,
                            d_pr_m, H_prev_m, rho_t_prev_kg_m3):
      # внутри рассчитать h(T_s), I(T_s), q_e, q_c, q_eff, q_s, q_i
      # и вернуть R(T_s)
  ```

- Реализовать solve_surface_temperature в виде одномерного численного решателя для R(T_s) = 0:

  - задать интервал поиска T_s:
    - T_min = min(T1_C, ta_C) - 30 °C
    - T_max = max(T1_C, ta_C) + 10 °C

  - вычислить R(T_min) и R(T_max):

    - если R(T_min) и R(T_max) имеют разные знаки → запустить метод бисекции на 20–30 шагов;
    - если знаки одинаковые → взять из T_min, T_max или исходного T1_C тот T_s, где |R| минимально.

- Ограничить итоговое T_s разумным диапазоном (например, [ta_C - 40; ta_C + 20]), чтобы итерация не уходила в экстремальные значения.

Комментарий:

- Это изменение влияет только на численный способ поиска T_s, но не меняет сами формулы (1)–(15).
- При необходимости можно вернуться к более простому решателю, если тесты покажут, что бисекция слишком тяжёлая или чувствительная к параметрам.
